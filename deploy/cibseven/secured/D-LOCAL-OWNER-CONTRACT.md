# D local owner: closed finite L1 contract v1

This is the ADR-0056 **inert contract**. Parsing, signature-shape checks and a legal state transition do not authenticate facts or authorize effects. The fixed producer, policy reader, durable journal and same-session composition are subsequent source work. No HTTP service is assumed.

## 1. Authority, identity and canonical bytes

The independently installed owner trust configuration supplies an Ed25519 public key/key ID, owner IAM ARN/RoleId and protected enrollment table ARN/TableId. The request process cannot choose or replace them. Trust installation and signer custody belong to a separate owner OS user/task. Its credentials and signing key never enter the test process, argv, environment dumps, receipts or logs. The future producer has no shell, listener, generic AWS/SQL command, dynamic plugin, arbitrary callback or caller-supplied client/cursor seam. A private Python member is not OS isolation.

The first profile is `maezo.d7-local-owner.fresh.v1`, mode `PUBLIC_SYNTHETIC`, partition `aws`, one account/region, one installation/run/scope, one fresh writer role, one fresh receipt-reader role and one fresh control table. No preexisting factory role/table, controller session, imported writer credential, cross-account/global-table/index/stream/TTL topology is admitted. An independently managed enrollment table and owner role preexist; they are actual trust inputs, not generated authority.

All records use the existing D canonical JSON codec: UTF-8, sorted keys, no whitespace, duplicate keys, floats, negative integers or unknown fields. Limit 131072 bytes, existing depth32/safe-integer bounds. UUIDs use the existing D UUID type. ARNs are exact scoped strings; no wildcard/path alias substitution. The source module `owner_local_contracts.py` is the executable closed field list for this additive protocol, not a replacement for D `Scope` or ADR-0055 `Enrollment`.

Three signed kinds: `intent`, `enrollment_operation`, `acquisition`. Envelope fields are exactly `protocol kind key_id body signature`; protocol `maezo.d7-local-owner.signed.v1`; signature is canonical unpadded base64url Ed25519 64 bytes. Signing bytes are `b"maezo.d7-local-owner.signature.v1\0" + canonical({protocol,kind,key_id,body})`. The unsigned `body` itself is canonical JSON. Kind/key/protocol are authenticated; swapping a signature among kinds fails. The inert parser checks encoding and associations only. A future concrete owner boundary must verify the signature against independently installed trust and actual protected records; there is deliberately no `verified=True` field or parser-produced authority object.

### OwnerIntent

Exact fields: `protocol mode profile enrollment_id installation_id run_id control_scope_id bootstrap_operation_id acquisition_id scope trust resources source not_before_ms deadline_ms operations`.

- Protocol `maezo.d7-local-owner.intent.v1`; operations exactly ordered `bootstrap_scope, install_d, readback` (not prepare or runtime).
- `trust`: exactly `key_id public_key_sha256 owner_arn owner_role_id enrollment_table_arn enrollment_table_id enrollment_reader_arn enrollment_reader_role_id owner_ingress_arn owner_ingress_role_id owner_source_identity`. This is an association to installed trust, not a way to install trust. Owner, enrollment-reader and ingress ARNs/RoleIds are pairwise distinct and account-bound; ingress is the independently controlled issuer of the initial owner capability. Source identity is an exact 2–64 character STS identity. Neither owner ingress nor enrollment-reader may equal a fresh factory role.
- `resources`: exactly `control_table_arn writer_arn reader_arn`. Names are fixed from installation UUID: `maezo-d7-<uuid>-control`, `maezo-d7-<uuid>-writer`, `maezo-d7-<uuid>-reader`; IAM path `/maezo-d7-synthetic/`. This prevents an acquisition from selecting arbitrary resource names. Owner/writer/reader distinct; enrollment/control tables distinct.
- `source`: exactly `git_sha tree_sha artifact_sha256 manifest_sha256 cib_abi_sha256 policy_profile_sha256`; first two existing GitOid, others SHA256. Hash association never substitutes actual source/readback.
- Intent lifetime positive and <=900000ms. The producer must finish before its actual remaining deadline; this does not shorten STS credentials below AWS's 900-second minimum. Writer credentials remain private and their full real expiration is recorded. No controller/candidate credential is issued by L1.

### Acquisition journal record

Exact fields: `protocol intent_sha256 acquisition_id revision state previous_sha256 evidence_sha256 recorded_at_ms`. Protocol `maezo.d7-local-owner.acquisition.v1`. ## 2. Protected keys, absence transactions and permanent collisions

The preexisting independently pinned enrollment table has only string PK/SK; no TTL, streams, replicas or indexes. One atomic absent-only transaction reserves **all** keys below with `attribute_not_exists(PK) AND attribute_not_exists(SK)`, full identical intent binding and immutable canonical bytes/hash. Transaction construction, signed intent/trust verification and strong readback are required future source. Partial fallback writes are forbidden.

| PK | SK | Permanently prevents |
|---|---|---|
| `D7LOCAL#INSTALLATION#<installation UUID>` | `RESERVATION` | Same installation under a new enrollment/run/op |
| `D7LOCAL#RUN#<run UUID>` | `RESERVATION` | Same run under a new installation/enrollment |
| `D7LOCAL#SCOPE#<sha256(canonical(Scope))>` | `RESERVATION` | Same complete DB/tenant scope under a new control-scope ID |
| `D7LOCAL#CONTROL_SCOPE#<control-scope UUID>` | `RESERVATION` | Control-scope alias across DB scope |
| `D7LOCAL#ENROLLMENT#<enrollment UUID>` | `RESERVATION` | Enrollment alias/collision |
| `D7LOCAL#BOOTSTRAP#<bootstrap-op UUID>` | `RESERVATION` | Bootstrap operation reuse |
| `D7LOCAL#ACQUISITION#<acquisition UUID>` | `CLAIM` | Duplicate issuer invocation |
| `D7LOCAL#RESOURCE#<sha256(canonical(exact ARN))>` (three rows) | `RESERVATION` | Role/table names reused after deletion or name alias |

Each binding is the complete intent SHA, installed trust/store incarnation, all intent IDs, exact scope and fixed resource names. A new key ID, operation UUID, enrollment alias, table recreation or independent process does not release anchors. Enrollment-store incarnation replacement is not supported recovery. Trust-owner replacement requires explicit separate preservation/review, not a newly empty store.

Journal rows use PK `D7LOCAL#ACQUISITION#<acquisition UUID>`, SK `EVENT#<revision as 10 decimal digits>`. Maximum revision64. Record1 is committed in the same absent-only transaction as reservations/claim. Each subsequent before-effect row is put absent-only in a transaction with a separate ConditionCheck on the distinct previous committed EVENT row, comparing its exact canonical bytes/hash. The absent-only Put and prior-row ConditionCheck are atomic; a pre-read alone, overwriting the prior row or adding a mutable HEAD cannot substitute. No mutable HEAD, DeleteItem, TTL or overwrite; a crash at any in-flight state leaves a consumed operation. Future code must check the entire exact prefix and latest revision with strong readback; blind append or acceptance of a hidden later event is forbidden.

The ADR-0055 control-table four-record installation/scope/ROOT/bootstrap transaction remains unchanged. These new enrollment-store reservations do not replace those four anchors or their orphan-partition preflight.

### Actual no-TTL observation

The future observer must call DescribeTimeToLive on each exact enrollment/control table ARN it is qualifying and bind the actual response to that table incarnation and current observation interval. Require the returned TimeToLiveDescription.TimeToLiveStatus to be exactly `DISABLED`; missing/null/unknown/ENABLING/ENABLED/DISABLING status refuses. DescribeTable has no TTL status, and omitted UpdateTimeToLive permission, a supplied digest or the fresh control table default does not establish the preexisting enrollment store state. The inert `require_disabled_ttl` validator checks only the closed TimeToLiveDescription value: required TimeToLiveStatus, optional AttributeName (string length1–255), no extra fields. A valid value does not authenticate a response, table identity or observation time. An optional returned attribute name does not replace genuine current DISABLED status as the precondition. No TTL mutation is granted. [DescribeTimeToLive](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_DescribeTimeToLive.html), [TimeToLiveDescription](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_TimeToLiveDescription.html).

## 3. Issuance and crash state machine

Only the process that successfully commits and strongly reads back the invocation's absent-only claim may continue in its existing execution. A restarted process may inspect/reconcile; it cannot infer it owns permission to issue. There is no claim lease, expiry reuse, `retry`, `force`, alternate UUID or replacement resource path.

Normal sequence (each arrow durable before next external effect):

`CLAIMED -> WRITER_CREATE_STARTED -> WRITER_CREATED -> READER_CREATE_STARTED -> READER_CREATED -> TABLE_CREATE_STARTED -> TABLE_CREATED -> ENROLLED -> ISSUE_STARTED -> ISSUED -> READER_ISSUE_STARTED -> READER_ISSUED -> BOOTSTRAP_STARTED -> BOOTSTRAPPED -> INSTALL_STARTED -> COMMITTED`.

- CreateRole stages include the fixed role inline-policy/trust configuration, absent boundary and complete readback before CREATED. Every individual mutating API call has its own private before/after subreceipt under that stage; an ambiguous subcall stops the stage. No successful state is inferred from an ARN existing.
- CreateTable carries the complete control-table policy in that request. Actual ACTIVE/TableId/policy/source readback precedes TABLE_CREATED. A matching later GetResourcePolicy is not a propagation oracle.
- ENROLLED requires committed, signed EnrollmentOperation plus the exact ADR-0055 Enrollment. It does not mean SQL installation occurred.
- ISSUE_STARTED commits before the one bootstrap `AssumeRole`. Its exact request is RoleArn=writer, RoleSessionName=`d7-<acquisition UUID>`, DurationSeconds=900, SourceIdentity=the exact inherited `owner_source_identity`, the fixed session policy below; no tags, transitive tags, managed PolicyArns, MFA or caller-selected fields. The owner role already has a genuinely issued protected capability; the factory never reissues an owner credential. STS SourceIdentity persists across role chaining: writer and reader retain the exact inherited owner_source_identity, while their distinct RoleSessionName values bind this acquisition and purpose. A conflicting or unknown inherited identity/transitive tag set refuses before issuance. Do not attempt to replace inherited SourceIdentity with the acquisition UUID.
- ISSUED requires actual returned assumed-role identity/RoleId, request hash, returned expiration and private delivery binding in the retained live process. No credentials are serialized to journal. READER_ISSUE_STARTED then READER_ISSUED durably surround exactly one separately journaled read-only reader AssumeRole, RoleArn=reader, RoleSessionName=`d7-r-<acquisition UUID>`, SourceIdentity=the same inherited `owner_source_identity`, DurationSeconds=900, exact reader session policy, no extra fields. Its handle goes only to the independent readback process through authenticated private custody. It has no bootstrap permissions. Unknown reader issuance also consumes the acquisition; it never retries writer or reader issuance.
- Network timeout, process crash, uncertain transaction/result/readback or issuer response loss at any step is `UNKNOWN` logically even if that row cannot be persisted. Strong readback may establish historical outcome, but never issue/deliver a new credential. No transition out of UNKNOWN or COMMITTED exists in v1. Read-only reconciliation returns separate historical evidence. A definitely denied effect is still consumed and marked UNKNOWN with its exact outcome, conservatively.
- A crash after a before-effect row but before the call consumes that operation too. This intentionally sacrifices retry availability to avoid double issuance; a new resource set needs fresh independently approved scope/installation/run and all collision checks.

### Private subcall journal contract (effect consumer not yet implemented)

Actual secrets in AssumeRole responses stay in private custody; hashes cannot restore a lost credential or authorize reissuance. Stage summaries list the exact ordered subcall hashes plus complete readback hashes; missing/extra/out-of-order subcalls prevent the successful stage. Indices and keys are fixed by API order, not a caller counter. The next effect slice must implement these exact closed subrecord parsers and transactions; this slice implements only the public intent/enrollment/acquisition parsers and session templates. No supplied subreceipt is currently accepted by runtime.
