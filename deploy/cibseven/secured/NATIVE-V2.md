## Trust and transaction

The exact mounted v2 policy is selected only by `MAEZO_ENGINE_BOUNDARY_V2_FILE` and `MAEZO_ENGINE_BOUNDARY_V2_SHA256`. V1 configuration remains required for the preserved human/v1 endpoints. Both are qualified as one installed layout; unsupported schema/version and mismatched mounted hashes refuse, with no negotiation or downgrade. V2 peers cannot be configured engine administrators. The servlet authenticates their direct certificate and sets their exact native user, no groups, and one tenant before entering the CIB executor.

`BoundaryPolicyV2` adds closed `database`, `admission` and `schema_digest` records to the existing boundary fields. `database` is `{database_oid,act_schema,act_schema_oid,migration_digest,database_binding_sha256}`. `admission` is `{activation_ref,database_incarnation,runtime_generation,epoch,decision_digest,purpose,admission_phase,account,region}`. These values are expectations compared with protected database state, not bearer grants. Account, region, incarnation, OIDs and digests use the closed D helper's scalar bounds. Runtime/candidate/restore qualification phases are explicit and cannot create missing qualification capability authority.

Capabilities use `maezo.engine-capability.v2`, exact schemas from the v2 resource and `{resource_requirement,source_requirement,source_owner_binding_digest}`. Locked-source bindings additionally identify the source owner's full workload identity, native user, worker, exact target and fetch capability digest. Owner identity, native acquisition reference and D generation remain separate. All parsed config/capability state is immutable. Outcome capability entries are exact `{digest,document}`; document is `{protocol,kind="outcome",identity,reader_native_user,reader_purpose,selector}` with selector `{engine,database_incarnation,identity,native_user,operation,capability_digest}`. The digest covers that exact document. This separately authenticated current reader is checked before any historical receipt lookup.

The native wrapper verifies actual JDBC PostgreSQL session/current user, database/ACT schema OIDs, READ COMMITTED and a non-autocommit enlisted session. Fixed MyBatis statements are dirty, uncached SELECTs that invoke only closed functions. Initial lock/statement limits are 1000/5000 ms; protected admission may shorten them. The D helper locks F then G; native locks admission/capability A, receipt R, the complete byte-ordered execution/task set P/T, then native acquisitions L. Duplicate lookup precedes task discovery. Same-row source/resource roles share a lock/reference and one native effect. Final checks re-enter only the already-held exact D F/G rows, retaining the original captured deadline; no later observation extends an in-flight authorization.

Fetch uses native null-or-expired (`<=`) expiry, null-or-active suspension and null-or-positive retries. It discovers a bounded complete set, locks it, rechecks eligibility and uses the real CIB per-task lock/projection implementation. At COMMITTING, after native flush, actual rows must all survive with exact ownership/expiry; each gets a new random 256-bit reference and revision 1. There is no post-commit output shrinking. Renewal preserves the reference and CASes the exact old revision to n+1 with actual post-renewal expiry, which may shorten. Completion, failure, BPMN error and unlock close the acquisition even where the native task remains. All consumed resource/source bindings include tenant, definition/topic, process/execution, worker, owner, activation, D generation/decision and native expiry.

All final native permissions, D authority/clock, post-effect row readback, acquisition mutations, technical receipt validation and complete response encoding occur before physical commit. SQL functions run on the same MyBatis session; no independent connection, commit or raw JDBC write is used. COMMITTED publication performs only an assignment of already encoded bytes. A missing publication, later listener failure or ambiguous commit response yields unavailability and requires exact outcome retrieval. It never automatically resubmits the effect, claims rollback or invents success. Read-only long-poll probes commit no receipt and release all locks before waiting; the final effect executes once.

The durable receipt contains only the exact command binding, pointer digests, consumed references and historical acquisition snapshots. Only first `executed` carries its transient projection. Duplicate/outcome returns the same technical receipt with no variable projection or live acquisition claim. Missing reconciled history returns unavailable; `not_observed` requires owner-proven complete history and never authorizes retry. Restarts discard caller-local handles; new acquisition always rotates its native reference. Restores require external D incarnation/highwater/credential reconciliation and current recovery authority, never backfilling or reviving old references.

Execute the reviewed output with the existing separately authenticated migration authority using psql; the script owns one BEGIN/COMMIT transaction and enables ON_ERROR_STOP. Do not run the raw template. The owner must already possess the narrowly qualified D installation-receipt/catalog readback and native schema/function ownership routes; missing privileges fail and never cause a broader grant. The script verifies D's exact component/version/predecessor, source/migration/installation/role/object digests and byte digests, local DB/schema bindings, the helper's exact owner/OID/source/security/search_path/ACL and absence of native runtime direct D access. The creation transaction rejects unexpected PUBLIC/default privileges, owner assumption and extra function/table/schema grants. The native function owner has only `UPDATE(command_id)` on immutable receipts because PostgreSQL requires one UPDATE column privilege for R row locking; no function contains any receipt UPDATE path. Each runtime/issuer call verifies native function-owner attributes and denies SESSION_USER membership in native/D owner roles. Native catalogue custody includes native definitions, OIDs, constraints, owners, ACLs and D helper/namespace custody. Before admitting a managed scope, the authenticated issuer invokes native registration only after the D guard independently authorizes registration for the selected protected phase/generation. Retirement requires the D generation already RETIRED and cannot reactivate it.

**Repeated D login preparation remains an explicit owner-interface prerequisite.** This finite installer pins one owner-prepared runtime login and rejects later native ACL drift.
