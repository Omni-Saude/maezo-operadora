# D7 startup containment v3: actual initializer admission

## Recommendation and scope

Use an explicit secured Server lifecycle adapter that can refuse policy admission **before invoking the vendor BPM platform deployment operation**. Keep the native WorkloadPlugin.preInit policy/layout/identity guard and its positive-path revalidation. Do not catch a failed engine build and continue Tomcat; vendor cleanup does not establish a safe empty runtime.

This is a new lifecycle allocation implementing existing ADR-0049 D7 and the unchanged D7B-ACCEPT-02 oracle. Record an ADR before implementation under docs/adr/README.md rule1; ROOT should allocate its number without overlapping native0051/D0052/reservedQ20053. This does not require a new business or user authorization decision. Independent design delta review is required before this source package proceeds. This revision addresses SC-F01–SC-F03 from ../d7-startup-containment-review/REPORT.md. Original DESIGN.md and its result remain unchanged. No source was edited for this design.

The scope is the existing opt-in secured v1 package and the three demonstrated stable startup faults (missing boundary CA mount, tenant mismatch, environment mismatch). It does not promise an HTTP404 for arbitrary late engine failures, broken TLS material, invalid container topology, native-v2 owner failures, or cleanup uncertainty. Those remain fatal startup failures and receive no D7B-ACCEPT-02 credit.

## Concrete minimum allocation

### A. Validate the transport independently of policy admission

Before a policy failure can be contained, verify the actual StandardServer instance and the exact already-pinned transport artifacts. Use the existing bounded canonical-path/digest reader against MAEZO_ENGINE_BOUNDARY_FILE/SHA256 to obtain the closed document and required file entries, but treat this solely as artifact custody, never as admitted identity/capability. All required descriptor file bytes must match their existing pins before reading the failing roots/peer identity admission.

Extract SecureLayout's pure structural checks so this path can validate its server/web/bpm descriptors without constructing a BoundaryPolicy whose CA/tenant/environment is precisely what is faulty. Do not duplicate or relax the existing checks: one Service/Engine/HTTPS connector, exact listener port, SSLEnabled/secure/https, required client certificate, no proxy/HTTP/AJP alternative, autoDeploy=false, exact filter/dispatcher/SPI/closed-UI/plugin structure, and the reviewed disabled-TRACE/first-valve boundary. Compare critical connector and lifecycle listener values with the actual Server object; a plausible unused XML file is insufficient. Missing/duplicate/wrong secured listener or an additional vendor bootstrap listener is fatal.

No transport fallback is installed. JSSE still uses its existing separately mounted PKCS12 truststore; the demonstrated missing /run/maezo/ca.crt is the boundary validator's CA file, not that JSSE truststore. Broken JSSE material cannot be converted into an authenticated404. The allowed transport exposes only Tomcat's standard failed-context response while the engine remains absent.

A missing/malformed custody document, descriptor hash mismatch, unsafe transport topology, unknown callback type or native-v2 mode is outside this first containment slice and must fail Server startup. This restriction prevents an invalid TLS/layout policy from being mistaken for a safe listener-only deployment.

### B. Secured lifecycle state and atomic boundary

New common-loader SecuredBpmPlatformBootstrap implements/delegates the pinned TomcatBpmPlatformBootstrap lifecycle (no vendor package shadow). Install it in place of the ONE vendor Server Listener via the secured fixture's pinned server.xml; the human/ordinary image keeps its vendor listener. Suggested closed states: NEW, STARTING, STARTED, PREFLIGHT_REFUSED, FATAL, STOPPED. Bind exactly one actual StandardServer and prohibit duplicate START/retry/same-JVM recovery. A new owned container is the recovery boundary.

At START, before creating any vendor deployment operation:

1. Verify transport and artifact custody as A; obtain a non-initializing empty-runtime baseline: direct ProcessEngines map, actual RuntimeContainerDelegate service inventory, relevant MBean names, no already-built WorkloadPlugin instance, and absence of owned jobs/acquisition/metrics executors. An unexpected existing engine or platform is fatal; do not close/adopt someone else's resources.
2. Validate actual BoundaryPolicy through its unchanged loader and full admission logic. All3 demonstrated faults already originate there. Catch ONLY the typed policy-unavailable Refused at this explicit preflight call after safe transport has been established. Record a closed PREFLIGHT_REFUSED outcome bound to server identity and observed public digests. Do not invoke vendor start, engine construction, job acquisition, platform plugins or managed thread-pool creation. Log a distinct truthful diagnostic, never forge the mandatory native filter/StandardContext markers.
3. On valid policy, set STARTING and invoke the original vendor deployment path. It builds the exact existing engine/plugins and still runs unchanged preInit guards. After success establish STARTED. Any exception after entering this path is FATAL and propagates to the original container failure/cleanup; never classify it as contained even when its leaf cause is Refused. A policy TOCTOU that fails preInit receives this fatal treatment.
4. On STOP after STARTED, delegate the existing vendor shutdown. On STOP after PREFLIGHT_REFUSED, there are no vendor-installed resources to stop, so do not call the vendor undeployer against nonexistent services. Duplicate/reentrant lifecycle events refuse.

An additional mandatory WorkloadPlugin preInit latch check for the deployed secured configuration can permit its single captured engine configuration only during this adapter's STARTING state, before the existing policy/layout checks. This prevents a later in-process engine construction after PREFLIGHT_REFUSED or silent duplicate bootstrap. The existing package-private PostgreSQL unit/integration constructor remains its explicitly scoped existing fixture seam; it must not become a deployed bypass. No production caller setter/reset/allow flag is introduced.

### C. Lazy REST listener: zero native/REST worker activation (SC-F01)

Replace exactly engine-rest's vendor FetchAndLockContextListener descriptor entry with a narrow Jakarta-compatible SecuredFetchAndLockContextListener in the existing REST-loader SPI artifact. Preserve original vendor class bytes and the actual pinned handler SPI. It owns a lazy vendor listener delegate and a closed once-only initialization/shutdown state, bound to the common-loader Server adapter and this exact ServletContext/Context.

On contextInitialized:

- Authenticate the actual shared adapter/server/context/classloader binding, not a boolean, environment switch, caller-provided callback or new ServiceLoader choice.
- For that adapter's terminal PREFLIGHT_REFUSED state, mark this listener REFUSED_WITHOUT_START and return. Do not instantiate the vendor delegate or handler, call handler.contextInitialized/start, load the handler SPI, register EXT_TASK_CONDITIONS, or throw early. Actual BoundaryFilter.init must still run and produce the required refusal/filter/context logs.
- For STARTED, instantiate the original pinned vendor listener once and invoke its unchanged contextInitialized behavior. Preserve its genuine live handler operations. A duplicate callback, mismatched/absent authority, changed ServletContext or invalid lifecycle state fails; it is not treated as a refusal/no-op.
- If a positive vendor initialization partially fails, this context is a failure requiring genuine cleanup. Do not report it as known preflight refusal. Track the initialized delegate's ownership so contextDestroyed invokes vendor teardown only for the actually owned initialized/entered delegate, at most once; record incomplete cleanup as a failure, without calling static vendor shutdown for a null/unowned handler.

On contextDestroyed after REFUSED_WITHOUT_START, mark terminally destroyed without touching vendor static state. No reset/retry/late STARTED transition is possible. No engine-specific background worker starts on this path; ordinary container/transport threads necessarily remain possible to serve mTLS404.

Pin the replacement listener, vendor handler SPI registration, common/REST classloader identities, and absence of a second original listener, duplicate descriptor registration or equivalent SCI path. Audit all other actual listener/SCI/filter constructors and init functions before activation. A failed BoundaryFilter alone is not this guarantee: StandardContext.filterStart attempts every filter definition. The inspected native ProcessEngineAuthenticationFilter init only constructs its configured CertificateAuthenticationProvider, whose constructor has no engine lookup; its lookup in doFilter cannot execute for an unavailable context. Any uninspected initializer is outside the admitted package.

### D. Real failed-context provenance and synchronous pre-connector gate (SC-F02/03)

BoundaryFilter.init must first require the exact secured adapter's STARTED state, then execute its existing policy/layout validation. In PREFLIGHT_REFUSED it records its actual typed refusal against this exact FilterConfig/ServletContext and throws the original Refused.unavailable exception. This terminal latch keeps every protected context unavailable even if mounted policy bytes are restored during startup. No synthetic HTTP response or forged log marker is introduced.

Install a narrow observer on the exact actual Engine's AFTER_START event **before Engine.start begins**. It runs synchronously inside Engine.start, before StandardService resumes its executor/mapper/connector loop. This is the enforcement point, not Server/Service AFTER_START. Retain post-start readbacks only as additional evidence.

Explicitly pin and verify actual getThrowOnFailure()==true on Engine, its Service and Server lifecycle owners. Check descriptor and actual object values, not Tomcat's default alone. Failure of the Engine observer must THROW and propagate through Engine.start -> StandardService.startInternal -> Server startup; never merely set Engine FAILED and return. Tomcat LifecycleBase.start treats an internally set FAILED state as controlled cleanup and can allow its parent to continue. In contrast, an exception from AFTER_START goes through handleSubClassException and is rethrown with throwOnFailure=true. Verify actual propagation in a real Tomcat lifecycle test, including controls with each owner property false. Refuse those topologies before starting Services.

After the Engine guard, only the reviewed ordinary transport/container executors and mapper/connector sequence may run. Forbid an unreviewed Service executor or lifecycle listener capable of bootstrapping an engine. Verify the actual listener/executor object inventory matches the pinned image and descriptors before this sequence. Connector bindOnInit may bind a socket before START; this design prevents acceptor/request-processing startup on failed guard, and does not claim zero earlier socket binding.

The Engine guard requires all of the following using only non-initializing observations:

1. The same immutable PREFLIGHT_REFUSED state, Server/Service/Engine/Context identities and intact transport/artifact custody. A changed graph, policy recovery, additional context, duplicate bootstrap or late callback cannot relabel this interval.
2. Actual BoundaryFilter refusal provenance for every required protected Context, actual native failed-start transition, completed cleanup and a currently unavailable state. Do not require only FAILED: normally Tomcat sets FAILED, performs stop, then ends STOPPED. Conversely an arbitrary never-started STOPPED context is not failure evidence.
3. Empty direct ProcessEngines registry and exact delegate/platform MBean service inventory; no native job/acquisition/metrics executor, no started fetch handler and no owned EXT_TASK_CONDITIONS registration. The refused lazy REST listener must show zero delegate/handler construction/init/start, not a worker that was started then stopped.
4. No active protected filter/servlet pipeline or alternate auto-bootstrap source. Runtime state is corroborating evidence; preventive installed-classpath/initializer admission is still required.

Concrete Context provenance hook: at Server START attach observers to the exact existing Hosts and any predeclared Contexts, and attach to each admitted dynamically added Context before it starts via ContainerBase.ADD_CHILD_EVENT. The pinned ContainerBase implementation emits ADD_CHILD_EVENT before child.start. Reject missing/late/duplicate observer enrollment and unexpected context identities. The Context observer records BEFORE_START, genuine BoundaryFilter refusal, BEFORE_STOP while getState()==FAILED, and AFTER_STOP with getState()==STOPPED. LifecycleState.FAILED itself has no event, so do not invent a FAILED_EVENT. LifecycleBase.stop explicitly fires BEFORE_STOP while retaining FAILED on the controlled failure path, making this a truthful observation. Correlate these records with the current-container StandardContext failure logs; no generic catch or synthetic marker substitutes for those logs. A state that is still FAILED or otherwise unavailable is accepted only if the required cleanup/ownership observations prove no live resources; STOPPED after the observed failed start is the normal required control. Prefer refusing ambiguous cleanup over enlarging a status set.

The guard must abort before connector acceptors if any evidence or cleanup is ambiguous. Such a run is a real failed startup and cannot earn authenticated404 acceptance. Preserve the exact unchanged404/body/title oracle for successful contained intervals.

Audit runtime classpaths and SCIs/listeners/filter constructors and init functions across every shipped webapp/common loader, including process-application descriptors, auto-bootstrap XML and provider registrations. Refuse alternate camunda.cfg.xml, activiti.cfg.xml, activiti-context.xml, a second engine/bootstrap SPI or a constructor that can create an unguarded engine. Never execute ProcessEngines.init(false) to prove absence. The secured image removes invoice and closes legacy camunda; actual artifact/ABI inventory must prove the remaining paths. No controller/native SQL/default changes are needed.
