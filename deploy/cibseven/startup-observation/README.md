# D7 opt-in startup observation source

This is source for one separately reviewed instrumented boundary run. It does not diagnose the failed source342 run, alter its evidence or provide engine acceptance. The actual engine source/image remains the separately pinned342 tuple; the observer JAR, JVM flags and compose mounts produce a different runtime configuration and must be identified as such.

`startup.jfc` enables exactly eight event families: execution/native samples at20ms; monitor-enter, monitor-wait and park waits at10ms threshold; thread CPU load at1s; data-loss notices; and the observer's own clock anchor. No file/socket/path/payload/environment/configuration events are enabled. Raw JFR remains private. Existing JVM options and JAVA_TOOL_OPTIONS are neither logged nor replaced; the compose helper requires the exact source-defined JAVA_OPTS default and appends fixed observer flags only.

`StageProjection.java` is compiled for Java17 and packaged with Premain-Class StageProjection. Premain starts a daemon observer and returns. Recording setup/configuration exceptions are caught in that observer; it does not exit the application. The recording name is MaezoD7Startup, disk retention8MiB, no exit dump, maximum observer lifetime300s. A fresh32MiB engine tmpfs contains the1MiB-chunk repository, fixed status file and eventual final dump together. The JFR retention setting alone is not a hard storage cap; the tmpfs is the aggregate cap. Heap/native overhead is separate. Sampling can perturb timing and can lose history. DataLoss absence does not establish complete retention.

The fixed FlightRecorderOptions are JVM startup options: an invalid repository can abort VM initialization before premain. A retained synthetic negative control proves this limitation. Agent exception handling is not a universal JVM non-abort guarantee. The valid flags and agent load were tested on the pinned host JDK; actual image execution and actual tmpfs exhaustion have not been tested. If instrumentation fails, preserve the original oracle result and classify the observation unavailable; do not infer a product TLS cause.

The successor instrumentation contract explicitly sets tmpfs UID1000/GID1000 while retaining mode0700 and every existing limit and flag. The exact image inherits camunda1000 in the finite Java17 preflight; workload342's operational fixture explicitly retains user0:0. Instrumentation preserves that existing user and entrypoint. A prior finite preflight refused during repository initialization under inherited camunda; the original mode0700 default-root tmpfs is incompatible with that user's writes. Closed predicates support the repository failure, but no corrected actual run has been performed and the original root-fixture startup cause remains unknown. This ownership amendment and its future exact preflight require separate independent review. Source evidence and the explicit amendment are in `strategy-cycle1-20260910/d7-instrumentation-repair` outside the repository.

The opt-in external wrapper adds instrumentation only after bootstrap seed and before the existing secured compose snapshot/cutover. It never adds a pre-oracle readiness wait. After the original ready child is terminal, a bounded collector reads the fixed agent PID/project status from the exact owned container, invokes the qualified image Java module launcher with one JFR.stop command, then privately copies only the owned observer tmpfs. Stop has at most5s; the two copies share at most10s; the whole command path and inherited identity checks share a15s deadline. Local process-group quiescence has the existing separate cleanup rules. Unknown remote attach completion keeps daemon uncertainty sticky and retains the lease/resources for owned recovery. The original failure/cleanup/oracle functions remain unchanged. A partial archive without a complete stopped recording stays UNAVAILABLE and remains private.

An independent machine-only offline consumer admits a root-pinned capture receipt and32MiB JFR from an owner-private archive. It reads at most100000 events,128 frames/event,600 aggregated rows and301 observer anchors, with a15s child watchdog,128MiB Java heap cap and256KiB public JSON cap. Only fixed stage/event/thread-role enums, bounded numeric observations and source/capture custody can escape. No arbitrary frame name, class, thread name, path, lock identity, log, exception or event field is projected. Unknown stages remain UNKNOWN.

Stage identity is an observed matching stack frame under the qualified image, not static reachability as execution proof. Execution/native samples are not complete phase durations or proof of continuous CPU work. Wait events show their own reported intervals; CPU load is a separate thread observation and is never joined to a stage by assumption. No wait-duration sum, parent-time partition or phase coverage assertion is made. The custom JVM anchors actually record System.nanoTime before/after System.currentTimeMillis; they remain JVM-local measurements, not a host/daemon clock bridge. JFR event Instants are not automatically aligned with the external readiness oracle. Clock adjustment, sample gaps, truncation, ring eviction, missing threads/stages and observer startup lag remain explicit limitations.

Its copied control suite is bound to that packet; this source worktree is not a merged implementation or a claim that ordinary CI has these external artifacts.
