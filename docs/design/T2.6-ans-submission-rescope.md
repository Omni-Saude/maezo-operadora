## 2. Mandatory-regardless items (design concretely; unblocked by DL-0029(a))

### 2.A Delete the fabricated-protocol path → labeled-mock ANS gateway (transport-triple, fail-closed)

**The defect.** `transmit_to_ans` mints a protocol from `sha256(time_ns)`:
```
ans_submit.py:220   protocolo_ans = f"ANSPROTO-{hashlib.sha256(str(time.time_ns()).encode()).hexdigest()[:16].upper()}"
```
This is the repo's canonical fabrication: it manufactures an official-looking ANS protocol for a filing that never happened, violating **Plan §0 ground rule 6** ("No fabricated integrations … never silent fabrication (cf. `ans_submit.py:209-212`)", `V2-COMPLETION-PLAN.md:17`) and the anti-fabrication discipline DL-0029 calls **"rule 3"** (`decisions-log.md:10`). It is **also a latent idempotency bug**: it is time-random, so the retry subprocess — which the BPMN documents as "protocolo_ans determinista por business_key (idempotente — nunca duplica filing)" (BPMN `:461`) — would fabricate a *different* protocol on every retransmit, contradicting its own non-duplication invariant.

**Replacement — an explicit ANS gateway behind an interface (the repo's established transport-triple pattern).** Mirror `dmn_transport.py` (`DmnTransport` Protocol / `CibSevenDmnTransport` real / `FakeDmnTransport`, ledger `:54`) and `mcp_cibseven/transport.py` (`CibSevenTransport`/`…HttpTransport`/`Fake…` + `start_process_idempotent`, ledger `:58`). Introduce:

```
class AnsGatewayTransport(Protocol):
    def submit(self, *, business_key: str, report_type: str, competencia: str,
               dataset_ref: str, revisor_id: str) -> AnsProtocol: ...
```
with **three** implementations, selected by config at boot and threaded to `submit_entry`/`retransmit_entry` via the existing `**seams` mechanism (`register_ans_submit_workers`, `ans_submit.py:444-487` — exactly how the `dmn` seam is threaded today):

1. **`RealAnsGatewayTransport`** — the real ANS webservice (`mcp-ans.submit`). **Blocked external** (no ANS credentials; Plan §7 `V2-COMPLETION-PLAN.md:179` "ANS webservice credentials"; issue #16, contract `SP-OP-ANS-SUBMIT-001.md:96,211`). **Not implemented in this task** — a constructor/`submit` that fails-closed (raises `AnsGatewayUnavailableError`) until a real endpoint + credential exist. Blocked ≠ done.
2. **`LabeledMockAnsGatewayTransport`** (dev/test **only**) — returns an **UNMISTAKABLY-SYNTHETIC** protocol that can never be mistaken for a real ANS one: e.g. `MOCK-ANS-NAO-VINCULATIVO-{business_key}`, plus explicit `synthetic: true` / `vinculativo: false` fields in the result. It is **deterministic by business key** (`ANSSUB-{tenant}-{report_type}-{competencia}`), which *also fixes the latent idempotency bug* — a retransmit returns the same synthetic protocol, honoring BPMN `:461`. **No `ANSPROTO-` prefix** (nothing that reads as official).
3. **`RefusingAnsGatewayTransport`** (the **production default until creds exist**) — **REFUSES**: raises a fail-closed `AnsGatewayUnavailableError` that the harness routes to human/incident (transient → incident-at-0, or an explicit `UT_TratarNack`-style human task). **In production configuration the gateway never returns a protocol at all** until `RealAnsGatewayTransport` is wired.

**Selection is fail-closed:** config (`MAEZO_ENV` / a `ANS_GATEWAY_MODE`) picks the transport; **if the environment is production and no real transport is configured → `RefusingAnsGatewayTransport`, never the mock.** The mock is unreachable in prod by construction.

**What does NOT change:** the `ERR_ANS_SUBMIT_NOT_HUMAN` guard stays exactly where it is and fires **before** any gateway call (`ans_submit.py:207-215`); the guard is orthogonal to the gateway and must be re-proven unchanged.

**Verification plan (R2 build, R1 verify — binding external act):** unit — mock returns a synthetic+flagged protocol and is deterministic across two calls with the same business key; refusing transport raises and is the prod default; the HITL guard still raises first when `decisao_envio`/`revisor_id` are missing. Update the two `ANSPROTO-` assertions (`test_ans_submit.py:154`, `:290-299`) to assert the synthetic label. Add a **fail-closed prod-config test** proving the production path returns *no* protocol. Integration — retransmit against the mock returns the *same* protocol (idempotency).

### 2.B TISS version pin + real XSD validation in `validate_data` (independent of SIP)

**The defect.** `validate_data` performs **no XSD parse**. It echoes `submission.schema_valid` and only checks `dataset_ref` non-empty / `dataset_complete` (`ans_submit.py:152-184`). The BPMN `ST_ValidateSchema` (`:153-158`) and the admissibility DMN input `in_schema_valid` (`ans_submission_admissibility.dmn:32-33`) both assume a *real* schema validation produced `schema_valid` — but nothing computes it (same non-computing fail-closed echo as `lgpd_anonimizado`, `review-queue.md:115`). This is **independent of SIP**: DIOPS, Monitoramento TISS, and the NIP filing all need schema validation.

**Design:**
- **Pin the TISS version.** Padrão TISS (Componente de Comunicação) is versioned under **RN 501/2022** (`rn-currency-review.md:48,83`). Store the pinned version in **config**, not hardcoded in the worker. The **exact version in force** is an SME question (§7 — regulatório).
- **Vendor the XSDs.** ANS publishes the padrão-TISS schema set as downloadable ZIPs (the "Padrão TISS" downloads page). Vendor the **full** set (the TISS XSDs `import` each other + reference dictionaries) into a checksum-pinned, provenance-documented directory — e.g. `spec/schemas/tiss/<version>/` — under the same checksum discipline T2.4 established (ledger `:56`). **Vendorable:** yes, the XSDs are public downloads; the open items are (i) the exact version and (ii) whether **DIOPS** flows through TISS XSD at all (DIOPS has its own economic-financial layout, not TISS) — SME question (§7).
- **Real validation, fail-closed.** `validate_data` loads the pinned XSD for the report type's schema and validates the assembled dataset XML with `lxml.etree.XMLSchema` (add `lxml` to `pyproject.toml`). **Fail-closed rules:** schema violation → `schema_valid=False` + structured errors → routes to `UT_CorrigirPendenciaEnvio` (never rejects, never auto-passes — preserves the admissibility DMN's no-reject invariant). **Missing/unvendored XSD for a report type → `schema_valid=False` → human** (never pass on absence). Because `assemble` is a stub today (mcp-regdata AWS-blocked, issue #16; `SP-OP-ANS-SUBMIT-001.md:94`), there is no real XML to validate → validation **stays False → human**, which is the correct fail-closed posture.

**Verification plan (R2 build, R1 verify — regulatory substance):** mutation test — corrupt a valid TISS XML → `schema_valid=False` → routes to human; a schema-valid XML → `schema_valid=True`. Missing-XSD → fail-closed. Stub/empty dataset → fail-closed (never green). Version pin surfaced in the audit record.
