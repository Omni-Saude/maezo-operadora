# Maezo — preserve all WIP on GitHub

Your only task is to find uncommitted source work and preserve it in GitHub commits. Do not implement features, fix bugs, run builds/tests, deploy, or merge incomplete work into main. A lower-cost coding model is suitable for this bounded task.

1. Read the latest `CHECKPOINT.md`, the current pointer in `PLANS.md`, and repository preservation rules in `CONTRIBUTING.md`. Verify your actual repository, branch, HEAD and status. Keep the original working directories and indexes unchanged.
2. Refresh refs without pruning. Inventory every registered worktree and the four standalone repositories named in the checkpoint. Collect tracked changes, staged changes and untracked source filenames with bounded parallel read-only Git commands. Record any inaccessible, missing or timed-out location explicitly.
3. Reuse existing preservation commits when their blobs exactly match the current WIP and their remote refs are verified. Do not create duplicate recovery branches merely because the original working directory still shows edits.
4. For uncovered WIP, inspect only the changed source. Exclude dependency folders, caches, raw logs, secrets, PHI and private evidence. Preserve excluded valuable material privately with hashes and its location. For partially staged files, preserve both the staged and working-tree versions if they differ; do not lose either.
5. Create an isolated `preservation/<date>-<worktree>` commit with the original HEAD as parent, using a temporary Git index or an existing clean released worktree. Include every eligible changed/untracked source file and intended deletion. Do not switch, reset, clean, stash, or amend somebody else's work. Check that source bytes did not change while taking the snapshot.
6. Skip build, lint, runtime and product-release gates for these explicitly unreviewed WIP snapshots. Still scan the new diff for secrets. If a scan flags a business identifier or synthetic fixture, inspect the exact finding and record its disposition; never suppress all findings. Real secrets or uncertain sensitive content stay private.
7. Push each preservation ref without overwriting existing refs. Verify the exact remote SHA and compare the published blobs against the source snapshot. Label the commit unreviewed WIP; publication is not source approval or release acceptance.
8. Update the existing `PLANS.md`, `RUNBOOK.md`, `CHECKPOINT.md` and current handoff pointer with paths, base/snapshot SHAs, remote refs, exclusions and unresolved items. Preserve frozen, hashed historical handoffs unchanged. Publish the sanitized current handoff too.

Stop when every discovered eligible WIP delta is represented by a verified GitHub commit, and every excluded or unresolved item has an explicit preserved location and reason. Report counts and refs, not a product-completion percentage. Do not delete worktrees or branches in this task; cleanup requires its own containment, custody, activity and dependency checks.
