# T2.4 (remainder) — A2A Agent Card Signing Gap (donor vs v2)

**Task:** T2.4 (remainder) — security-hardener (R2).
**Date:** 2026-07-17
**Scope:** item 5 of the T2.4 remainder charter — "A2A agent-card signing:
donor-vs-v2 gap analysis; if restoration is beyond workflow scope, write a
precise gap note ... (do NOT half-implement crypto)."
**Verdict: beyond workflow scope. NOT implemented in this PR.** `src/**` is
untouched by this change (this PR is CI/workflow-only, per the T2.4 remainder
charter's own FORBIDDEN list, which permits an A2A signer edit only if it is
"trivially self-contained" — it is not; see below).

## What v1 (donor, READ-ONLY: `/Users/familia/code/Maezo-Healthcare-Plan`) has

The donor's A2A layer (`src/maezo/a2a/registry.py`, `assembly.py`) implements a
complete Agent Card signing slice (closes the donor's own "GAP #9",
ADR-0003/0007):

- `AgentCard` is a **frozen dataclass** carrying `agent_id`, `version` (hash of
  the effective `AgentDefinition`), `tenant`, `security_zone`, `capabilities`,
  `skills`, `accepted_task_types`, `federation_layer`, `endpoint`,
  `queue_ref`, and a `signature: str | None` field.
- `AgentCard.signing_payload()` — canonical `json.dumps(..., sort_keys=True,
  separators=(",", ":"))` bytes over every field except `signature` itself
  (order-independent: sorted sets), so signing is stable and idempotent.
- `CardSigner` (`registry.py:183-236`) — HMAC-SHA256 over `signing_payload()`,
  versioned scheme prefix (`v1:<hex>`), constant-time verify
  (`hmac.compare_digest`), **fail-closed constructor** (raises
  `CardSignatureError` on an empty signing key — mirrors
  `gateway.pseudonymizer.Pseudonymizer`'s injected-key contract), plus
  `require_valid()` for a raise-on-invalid variant.
- `AgentCardRegistry` (`registry.py:239-291`) — `register()` takes an
  optional `verifier: CardSigner`; when injected, an unsigned or tampered Card
  is **refused at admission** (`CardSignatureError`), so the dispatcher only
  ever performs `lookup()` on Cards that already passed verification. Without
  a verifier (dev path), unsigned Cards are accepted — the gate is on key
  *presence*, not a separate feature flag.
- `assembly.build_agent_cards(..., signer=...)` / `card_signer_from_key(...)`
  — the vault/KMS injection seam: a real signing key is a **blocked external
  secret** (§6.2 in the donor's docs), so `card_signer_from_key(None)` returns
  `None` and the dev path stays unsigned-but-functional; production wiring is
  "inject the key, everything else already works."
- `tests/unit/a2a/test_card_signing.py` — 20 tests covering: sign/verify
  round-trip, HMAC-SHA256-over-canonical-bytes equality, idempotent
  re-signing, wrong-key rejection, set-order independence, tamper detection
  (parametrized over *every* covered field), cross-card signature swap
  rejection, empty-key fail-closed, unsigned-card-never-verifies,
  `require_valid` raise semantics, registry admits-only-signed /
  backward-compatible-without-verifier, `build_agent_cards` signs-when-signer
  vs unsigned-without-signer, full dispatcher build/route rejection of
  unsigned/tampered/wrong-key Cards, and fail-closed handling of an unknown
  signature scheme / garbage signature string.

## What v2 (this repo) has today

`src/maezo/a2a/card.py` — a **plain, non-frozen class** with `agent_id`,
`capabilities: list[str]`, `endpoint`, `public_key: str`, and `to_dict()` /
`from_dict()`. No `version`, `tenant`, `security_zone`, `skills`,
`accepted_task_types`, `federation_layer`, or `signature` field. No sign/verify
method, no canonical payload, no `CardSigner`, no `CardSignatureError`.

`src/maezo/a2a/registry.py` — `A2ARegistry.register(tenant, card)` takes the
tenant as a **separate call argument** (the donor bakes `tenant` into the Card
itself and derives the registry key from `card.tenant`); no `verifier`
parameter exists at all, so there is no way to gate admission on a signature —
there is nothing to gate, since no Card carries one.

`src/maezo/a2a/__init__.py` exports only `AgentCard`, `A2ARegistry`,
`AntiLoopGuard` / `CyclicDelegationError` / `MaxDepthExceededError`. There is
**no `assembly.py`, no `dispatcher.py`, no `idempotency.py`** in v2's `a2a/`
package — the donor's `DelegationDispatcher` / `FactProducer` /
`IdempotencyStore` / `build_dispatcher()` / `build_agent_cards()` machinery
that the signing slice plugs into does not exist in v2 yet. Confirmed via
`find src/maezo/a2a -type f` (4 files: `anti_loop.py`, `registry.py`,
`__init__.py`, `card.py`) against the donor's 4 files
(`registry.py`, `assembly.py`, `dispatcher.py`, `__init__.py`) — the file sets
barely overlap and the ones that share a name (`registry.py`) have a
materially different `AgentCard` shape and a different registry call
signature.

## Why this is not "trivially self-contained" (and was not implemented here)

Restoring signing faithfully requires, at minimum:

1. Redesigning `AgentCard` as a frozen dataclass with the additional
   `version` / `tenant` / `security_zone` / `skills` / `accepted_task_types` /
   `federation_layer` / `signature` fields and a `signing_payload()` method —
   a breaking change to the existing `AgentCard.__init__` / `to_dict` /
   `from_dict` contract and every call site that constructs one today.
2. Adding `CardSigner` + `CardSignatureError` (new crypto primitive, new
   exception hierarchy) with the fail-closed-empty-key contract and
   constant-time verification — exactly the kind of "half-implement crypto"
   this task's charter says not to attempt inside a CI/workflow-scoped PR.
3. Reworking `A2ARegistry`'s call signature (`register(tenant, card)` →
   `register(card)` with `verifier` gating) — a second breaking API change,
   independent of the signing feature itself.
4. There is no `assembly.py` / `dispatcher.py` in v2 to wire a `signer=`/
   `verifier=` parameter through in the first place — the donor's signing
   slice is bolted onto machinery (`build_agent_cards`, `build_dispatcher`,
   `DelegationDispatcher`) that v2 has not ported yet. Signing cannot be
   "restored" onto a dispatcher that does not exist without first deciding
   how/whether to port that dispatcher — a design decision (and its own task)
   well beyond a security-hardening CI PR.
5. A full equivalent test suite (20 tests in the donor) would be required to
   make any of the above trustworthy — none of which is reviewable or
   verifiable within this PR's stated scope (workflow files + docs).

Each of these is independently a real implementation task with its own
design/review cycle, not a drop-in port. Attempting any subset in isolation
(e.g. bolting a `signature` field onto today's `AgentCard` with no
`CardSigner`, or a `CardSigner` with nothing that calls `verify()`) would be
exactly the "half-implement crypto" outcome this charter forbids — a Card
that *looks* signed-capable without a verifying chokepoint is arguably worse
than the honest, undocumented gap that exists today.

## Recommendation / follow-up

Track A2A Agent Card signing restoration as its own task in
`docs/prompts/V2-COMPLETION-PLAN.md` (a security-relevant successor to
whichever task ports `assembly.py` / `dispatcher.py` / `idempotency.py` from
the donor, since signing has no host to attach to until that dispatcher
exists in v2). Suggested scope for that task:

1. Port `assembly.py` / `dispatcher.py` / `idempotency.py` (or v2's
   equivalent design) first.
2. Port `AgentCard` (frozen dataclass + `signing_payload()`), `CardSigner`,
   `CardSignatureError`, and the registry `verifier=` gate byte-faithfully
   from the donor (`src/maezo/a2a/registry.py:1-291` in
   `Maezo-Healthcare-Plan`), adjusting only for v2's actual `AgentDefinition`
   / tenant model.
3. Port `tests/unit/a2a/test_card_signing.py` (20 tests) unchanged in intent.
4. Wire the vault/KMS signing-key injection seam (`card_signer_from_key`) —
   the actual key material stays a blocked external secret, exactly as in
   the donor.

This PR does not touch `src/maezo/a2a/**` or any other `src/**` path.
